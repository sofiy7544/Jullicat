# 🏁 Нитро-Двор — драг-рейсинг для браузера

Уличный драг-рейсинг в духе социальных браузерных игр 2009–2012 годов: вид сбоку, две полосы,
трибуны, стартовый светофор, глянцевые кнопки, неон и мокрый асфальт. Работает в Safari на iPhone
(мультитач) и на компьютере (клавиатура/мышь). Вся графика рисуется процедурно на Canvas 2D,
все марки, машины, трассы и названия вымышленные.

```
dragrace/
├── shared/   общая логика: физика, машины, детали, экономика, карьера, операции над профилем, протокол WS
├── client/   TypeScript + Vite, Canvas 2D, Web Audio, PWA
└── server/   Node.js + Fastify + Prisma/SQLite + WebSocket
```

| Античит | сервер хранит профиль и машину; клиент отправляет только запись нажатий; сервер повторяет заезд той же детерминированной физикой и сам считает время, награды и износ; проверка правдоподобия записи; защита от повторной отправки |

### Почему античит работает
Физика написана только на `+ − × ÷ sqrt` (без `Math.exp/pow/sin`), поэтому результат бит-в-бит
одинаков в Safari, Chrome и Node. Клиент присылает список `[тик, кнопка, значение]`, сервер берёт
**свою** копию машины игрока, прогоняет симуляцию и бота-соперника с тем же сидом — и только
после этого начисляет деньги. Подделать время, деньги или детали с клиента нельзя.

## Запуск

Нужен Node.js 20+.

```bash
cd dragrace
npm install            # ставит все пакеты и генерирует Prisma-клиент
cp server/.env.example server/.env
npm run dev            # создаёт SQLite-базу, запускает сервер :8787 и клиент :5173
```

Откройте http://localhost:5173. Можно играть гостем (всё хранится в `localStorage`) или
зарегистрироваться — тогда прогресс на сервере и доступны друзья, рейтинги и онлайн.

Проверки:
```bash
npm test                 # физика: таблица машин, детерминизм повтора
npm -w server test       # сквозной тест сервера (сервер должен быть запущен): аккаунты, античит, призраки, друзья, подарки, онлайн-матч со ставкой
npm run typecheck
```

Для теста турнира в будни: `TOURNAMENT_ALWAYS=1` в `server/.env`.

## Открыть на iPhone (та же Wi-Fi)

1. Компьютер и iPhone — в одной сети Wi-Fi.
2. `npm run dev` — Vite слушает `0.0.0.0` и печатает адрес:
   ```
   📱 Открой на iPhone (та же Wi-Fi):
      http://192.168.0.105:5173
   ```
3. Откройте этот адрес в Safari. API и WebSocket идут через тот же порт (прокси Vite), отдельный адрес сервера не нужен.
4. Поверните телефон горизонтально. «Поделиться → На экран Домой» — запуск на весь экран.

Особенности iOS Safari, которые учтены: звук включается после первого касания (Web Audio
разблокируется на `touchstart`), запрет зума двойным тапом и щипком, `viewport-fit=cover` и
отступы `safe-area-inset-*`, мультитач через Pointer Events с `touch-action: none` — газ и
передачу можно жать одновременно. Вибрации в iOS Safari нет — она заработает в Capacitor-сборке.

Если macOS спрашивает про входящие подключения для Node — разрешите. Если страница не открывается,
проверьте, что Wi-Fi не «гостевой» (в них устройства изолированы друг от друга).

## Деплой

### Вариант 1: всё на одном сервере (проще всего)
Сервер сам раздаёт собранный клиент из `client/dist`.

**Render** → New Web Service → репозиторий, Root Directory: `dragrace`
- Build: `npm install && npm run build`
- Start: `npm start`
- Env: `DATABASE_URL=file:/var/data/prod.db`, `CORS_ORIGIN=*`
- Добавьте Persistent Disk, смонтированный в `/var/data` (иначе SQLite обнулится при деплое).

**Railway** — так же: Root `dragrace`, те же команды, Volume в `/data` и `DATABASE_URL=file:/data/prod.db`.

### Вариант 2: клиент на Vercel, сервер на Render/Railway
1. Сервер — как выше, но `CORS_ORIGIN=https://ваш-проект.vercel.app`.
2. Vercel → New Project → Root Directory `dragrace/client`,
   Install: `cd .. && npm install`, Build: `npm run build`, Output: `dist`,
   переменная `VITE_API_URL=https://ваш-сервер.onrender.com`.
3. WebSocket подключается к тому же хосту, что и API (`wss://…/ws`).

На бесплатном Render сервер засыпает — первый запрос может идти ~30 с; клиент повторит запрос сам.
Для роста: SQLite → PostgreSQL заменой `provider` в `schema.prisma`.

## План упаковки

Код уже разделён так, что платформа подключается в одном месте — `client/src/platform.ts`
(вибрация, параметры запуска, адрес API), а авторизация на сервере — модуль `server/src/auth`
с провайдерами.

### VK Mini App
1. Создать приложение в VK, указать URL клиента (Vercel) в настройках Mini App.
2. Подключить `@vkontakte/vk-bridge`, в `main.ts` вызвать `bridge.send('VKWebAppInit')`.
3. Авторизация: эндпоинт `POST /api/auth/vk` **уже есть** — он проверяет подпись параметров
   запуска (`vk_*` + `sign`, HMAC-SHA256 с `VK_APP_SECRET`) и создаёт/находит игрока по `vk_user_id`.
   На клиенте: `platform === 'vk'` → отправить `vkLaunchParams()` вместо формы ника/пароля.
4. Социальное: друзей подтягивать из `VKWebAppGetFriends`, вызов друга — `VKWebAppShowRequestBox`,
   «стену» дублировать в `VKWebAppShowWallPostBox`; подарки — внутриигровые как сейчас.
5. Платежи (позже): голоса VK → кристаллы, начисление только на сервере по callback-уведомлениям VK.
6. Учесть iframe: без `localStorage` в некоторых WebView — гостевой режим заменить на VK-авторизацию.

### iOS через Capacitor
1. `cd client && npm i @capacitor/core @capacitor/cli @capacitor/ios @capacitor/haptics @capacitor/screen-orientation`
2. `npx cap init "Нитро-Двор" com.example.nitrodvor --web-dir=dist`, затем `npm run build && npx cap add ios`.
3. В сборке задать `VITE_API_URL` на продакшен-сервер (в нативном приложении нет прокси Vite).
4. Вибрация уже работает: `haptic()` в `platform.ts` вызывает `Capacitor.Plugins.Haptics`, если он есть.
5. Ориентация — landscape (Info.plist), статус-бар скрыть, `contentInset: 'never'` — safe area уже учтена в CSS.
6. Звук: в WKWebView Web Audio тоже требует жеста — разблокировка по первому касанию уже есть.
7. Вход: Sign in with Apple (требование App Store при наличии других входов) — добавить провайдер в `server/src/auth`.
8. Покупки (если появятся): StoreKit через плагин, проверка чеков на сервере.

## Архитектура вкратце

- **shared** — единственный источник правил. `ops.ts` — все операции над профилем (покупка, ремонт,
  тюнинг, бонус, задания, применение результата заезда). Гость выполняет их локально, аккаунт —
  через `POST /api/op`, где сервер выполняет тот же код над профилем из базы под блокировкой.
- **client** — без фреймворков: экраны в `src/ui/screens`, сцена заезда `src/game/raceScene.ts`,
  отрисовка машин `carArt.ts`, фоны трасс `scenery.ts`, звук `audio.ts`, данные `api/service.ts`.
- **server** — `routes/game.ts` (профиль, заезды и их проверка, турнир, призраки),
  `routes/social.ts` (друзья, рейтинги, стена, подарки), `ws.ts` (лобби, чат, подбор по силе,
  вызовы, ретрансляция позиций, итог онлайн-матча и выплата ставок).

Онлайн-заезд: сервер создаёт матч с общим сидом и временем старта, списывает топливо и ставки в банк,
клиенты синхронизируют часы через ping и гоняют свою машину локально, позиции соперника приходят
~15 раз в секунду с интерполяцией. Итог считается по проверенным сервером записям обоих игроков;
победитель получает банк минус 5 %.
